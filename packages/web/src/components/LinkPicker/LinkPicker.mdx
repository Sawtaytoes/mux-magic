# LinkPicker

A picker for path-link fields. Lets the user point a step's input at either a named **path variable** (declared at the top of the builder) or the **output folder of an earlier step**. Any step *after* the current one is excluded — links can only flow forward.

Rendered **inline** at each link-button site (`PathField`, `StringArrayField`) as a Charcuterie `Combobox`: the trigger is its own button and the searchable popup portals itself to the body, anchored off the trigger by `useAnchoredOverlay` (no hand-measured `triggerRect`). Reads `stepsAtom` and `pathsAtom` directly so the option list stays in sync as the builder mutates. Selection writes through `useBuilderActions().setLink(stepId, fieldName, value)`.

## Props

| Prop | Role |
|------|------|
| `stepId` | The step whose field is being linked |
| `fieldName` | The field on that step |
| `label` | The current link's display label, shown on the trigger button |

## Behaviour

- **Open** → clicking the trigger toggles the Combobox. The option list is built fresh each open: all path vars first, then earlier steps' output folders (skipping steps with `command === null`), plus a row per declared named output.
- **Position** → `useAnchoredOverlay` flips and clamps the popup to the viewport; no bespoke `computePosition`.
- **Initial selection** → derived from `step.links[fieldName]`: a string matches a path var, `{ linkedTo, output }` matches a step output. Shown with the Combobox's ✓.
- **Search** → matches `label` or `detail` (case-insensitive) via each option's `textValue`.
- **`acceptedOutputs` whitelist** → when the anchor field declares it, path-variable rows and folder rows are hidden and the footer hint is suppressed.
- **Detail rendering** → path values inject zero-width-space breaks before separators so long paths wrap cleanly.
